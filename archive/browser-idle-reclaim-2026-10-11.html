Hermes 浏览器空闲回收 · 核实报告

对象：Herme（LXC 105 容器上的 Hermes Agent，v0.21.6+140）｜时间：2026-10-11 凌晨（CST）｜验证方式：真机实测 + 源码比对

结论：那个每 15 分钟的定时回收任务不能删

内置回收确实存在，但它只管到 chrome 这一层；链路最上层的 harness 守护进程（每个约 22–42 MB）不在内置回收范围内，既没有空闲自退，内置 orphan killer 也扫不到它 —— 这一层目前只有那个 cron 收割器在兜底。

一、浏览器链路分层：哪层会自己下班

browser_exec（下指令）
  └─ harness 守护进程（bu-default，翻译官） ✗ 没人叫它走，它就常驻
     └─ agent-browser 守护（司机）       ✓ 120 秒空闲自退
        └─ chrome（车）＋临时 profile  ✓ 120 秒空闲全退，目录自动删

一句话：车和司机都会自己下班，翻译官没有下班机制。

二、真机实测：空闲 200 秒后剩谁

步骤：调一次 browser_exec 打开页面 → 放着完全不管 → 200 秒后按 /proc 逐个核对身份（不用字符串匹配，直接读命令行 argv）。

同事文档里「120 秒空闲 → 整块浏览器回收、标签消失、临时 profile 删除」这一条，实测完全属实。它作用的对象是 chrome 与 agent-browser 那一层，不含 harness 守护。

四、同事文档逐条核对

说对的三条

  • 120 秒空闲回收整块浏览器、标签消失、临时 profile 删除 —— 实测确认
  • orphan killer 每 5 分钟一轮、宽限 1 小时 —— 源码常量确认（300s / 3600s）
  • 退出时 atexit 再收一次 —— 源码确认，并且当晚实测到：网关 01:08:20 重启，harness 守护随即消失

漏的一条（关键）

  • harness 守护进程这一层没有任何自动回收：不随 120 秒超时走，也不被 orphan killer 覆盖，只在「驱动它的 Hermes 进程退出」时才被顺手停掉。网关常年不重启时，它就无限期常驻

同事那边大概率同样存在，只是没往这一层看。

六、建议

  • 保留 cron：纯 shell 脚本、零 token 成本、每 15 分钟一轮，只在「真没人用」时才动手；误杀代价是下次调用自动重拉（秒级）。
  • 可选收窄：chrome 与 agent-browser 那半截已经内置自清，脚本可以只保留「收 harness 守护 + 清死会话的端点空壳」，减少误杀面。
  • 不建议删：删掉后每开一个新名字的浏览器会话都会留下一个常驻守护，网关越久不重启攒得越多。
